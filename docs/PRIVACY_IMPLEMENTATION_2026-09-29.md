Название: техническая проверка и подготовка публикации.
Цель: сохранить сайт с прямыми контактами без необязательного сбора данных.
Шаги: проверить исходники; добавить правдивое описание; проверить публичный пакет.
Срок этой версии: 29 сентября 2026. Публикация после проверки владельцем.
Владелец технической приёмки: Динар.

## Результат

В исходной финальной версии нет форм приёма заявок и аналитических счётчиков. Добавлена техническая страница public/privacy/index.html и постоянная ссылка в шаблоне scripts/build.mjs. Пересобраны 12 существующих страниц. Адреса, содержимое услуг, контакты, robots.txt и sitemap.xml сохранены. Техническое описание не заменяет полную политику фактического оператора.

## Не выполнено автоматически

От маминого ИП уведомление РКН НЕ подавалось. Эта правка ничего не подаёт и не назначает мамино ИП оператором dinar.moscow. Для проекта подтвердить реального исполнителя и оператора, его реквизиты/адрес, почту, доступы, основания и сроки обработки обращений, местонахождение баз и журналов, требуемое уведомление. Не менялись DNS, хостинг, права доступа и исторические данные аналитических кабинетов. Российский хостинг сам по себе не закрывает обработку писем и заказов.

## Пакет для REG.RU

`npm run build && npm run check` проверяет сайт. Затем `python3 tools/package_public.py` создаёт dist-regru только из public/. Не выгружать .git, docs, tools, исследования и клиентские материалы.

Workflow публикации в этой ветке НЕ подключён. Референсная реализация: TerrificKook/dinarcraft, коммит 652827571b619ab428b0735fa0d4a58b4b7b2c0e, файл .github/workflows/deploy-regru.yml. Она подготовлена для отдельного этапа настройки, а не выполняет перенос сейчас. Нужны подтверждённые SSH/rsync, адрес сервера, пользователь, порт, отдельный каталог и ключи в GitHub Secrets. Закрытые ключи не публиковать, ключ сервера проверить у провайдера. Не отключать проверку ключа сервера.

## Переезд без смены рабочего процесса

1. Проверить имеющуюся услугу «Хостинг - 1»: статус, тариф, SSH/SFTP и лимиты.
2. Подтвердить российское размещение услуги, почты, журналов и резервных копий.
3. Загрузить публичный пакет в отдельный пустой каталог; проверить страницы, контакты, ресурсы и HTTPS до смены DNS.
4. Сохранить DNS-зону; менять только необходимые A/AAAA/CNAME, сохраняя MX/SPF/DKIM/DMARC/TXT. Не менять NS без переноса зоны.
5. После проверки новой публикации отключить текущий GitHub Pages и workflow preview.yml, но не раньше.
6. После ручной проверки подключить обновления из GitHub на REG.RU. Исходники остаются в GitHub, туда не передаются письма, логи и клиентские базы.

Смена регистратора, новая CMS, база MySQL и отдельный VPS ради этих страниц не нужны. Общую сумму и условия хостинга проверить до оплаты. Это технический этап, не заключение о полном соблюдении 152-ФЗ.
